# PTC Exams App

A lightweight, browser-only tool for polytechnic board exams: reads DOTE **Nominal Roll** and **Hall Ticket** PDFs, works out question-paper needs and builds the seating arrangement.

**Live app:** https://iammannan.github.io/ptc-exams-app/

## Screens
1. **Home** – a flow chart of how the app is used, with the progress of each step. Click a step to open it.
2. **Nominal Roll Upload** – select many nominal roll PDFs at once. Each student's name, reg no, DOB, course, semesters, regulation, exam type (R/S) and sem-wise subject codes are read and verified against the *Subject Count*, *Semesters*, *Total Students* and header *Student Count*. After an upload the screen confirms success with the parsed student count and the total student count from the roll.
3. **Hall Ticket Upload** – upload DOTE hall ticket PDFs (one per course). Every subject's sem, regulation, exam type, exam date and session is read, tickets are verified (missing fields, unreadable dates, session clashes), and each ticket is cross-checked against the nominal roll. **Differences / Mismatches** lists candidates missing on either side, name or course differences and subject code mismatches (export as CSV or PDF).
4. **Candidates** – students from the nominal roll ("Student details displayed here are sourced from the Nominal Roll"). Filter by course, subject code (or both), exam type, name / reg no; export CSV or PDF. **Add, Edit, Delete** students: your changes are kept on top of the uploaded rolls, so re-uploading a roll doesn't lose them. A student corrected here writes only the subjects kept in the edit: hall-ticket subjects you removed are left out of QP statistics, seating and the timetable clash check, which is re-run on every load (two codes of the same question paper are not a clash).
5. **Equivalent Subjects Mapping** – the built-in **DOTE equivalent subjects table** (1,025 K / L / M / N scheme subjects across 9 courses, each mapped to its newer subject; chains such as L → M → R2023 are followed) is applied automatically and can be switched off. **Upload equivalents table** (.xlsx / .csv in DOTE's format: Sno, CNO, SUBCODE, SUBNAME, SEM, COLNO, ELEC, Elective, REGL, EQC — a template can be downloaded) replaces it with a newer list in this browser; *Use built-in table* switches back. **Export mappings (.xlsx)** saves custom (yours), default (the DOTE table) or both, for all courses or one course (CNO = course code; part-time / Tamil-medium courses get their full-time course's table rows, noted in SOURCE), in the same format, ready to upload again. Add your own mappings — one **Current Subject** (course → scheme → semester → subject) to any number of **Old / Legacy Subjects** (*+ Add extra old subject*) — to add or override equivalents; yours always win. Mappings are per course: the same current subject code can be mapped separately for, say, 1020 and Tamil-medium 7020. The pickers list every subject of the course: those on the hall tickets with their candidate counts first, then every time-table subject and every old-scheme subject from the built-in table, shown with (0) when no student writes it. Search a subject code or name to see the merged subject with every legacy code and candidate counts. A student with two old subjects that map to the same current paper (e.g. sem 3 and sem 4 arrears) counts once: one QP, one seat, one row in every export. Seating keeps one seat per student per session; repeated seats saved earlier are removed automatically (the seat for a paper still in the session is kept). Part-time (3xxx) and Tamil-medium (7xxx) courses use the full-time course's equivalents.
6. **QP Statistics** – one page with options. **Candidates:** hall tickets (HT) and / or the nominal roll (NR adds students and subjects missing from the hall tickets, dated from the time table). **Dates from:** time table, hall ticket, dates set by you — a subject takes the time-table date only where the time table lists both its code and the student's course (or the common first-year course 1000 / 3000). **Subjects:** default mapping (the built-in DOTE equivalents table) and / or custom mapping (yours) — each subject lists all its equivalent codes with candidates, our courses only (those on the nominal rolls), show time-table subjects nobody writes. **Group by:** day, session or course — every grouping shows the paper rows (click for candidates, ✎ to edit a date, merge icon to join course codes that share a QP — merged rows also share a row in the Hall Allocation sheet). **+** on each session opens a list of subjects to add there: the same subject code timetabled for another course in that session, and subjects with no date that are not mapped (old schemes; current-scheme ones on request); adding sets that session as their date. **✕** on a paper row removes that course's paper from the session (QP statistics and seating); it is listed under the session's **+** to restore. A **session-wise count** chart (FN and AN on each bar) and table head the page. A student under two papers in one session counts once (ⓘ explains it). Subjects with no hall-ticket date whose code the time table lists only for another course are listed under **Same subject code, other course**: add each on that course's date or hold it. **+ Add missing dates** / ✎ set dates, with lab slots (9 – 12, 12 – 3, 3 – 6) and batches. Past exam days fold away. Export CSV / PDF (the PDF starts with the session-wise count and chart). The *Exam schedule & student lists* view has the day-wise dashboard and per-exam student lists PDF.
7. **Seating** – set up halls (columns × rows, seats A1…E6). Pick an exam date and session to get the waiting candidates, split Regular / Supplementary and grouped by course or by subject code — groups never mix course codes. Select seats like a spreadsheet and pick a group: register numbers are always laid in ascending order. **Auto plan** seats every waiting candidate at once: column by column (A1…A6, then B1…), each course + subject in ascending register numbers, never two of the same course or subject code side by side, filling the halls from the first one in the list until everyone is seated; tick **Zigzag** to run columns A, B downwards, C, D upwards, E, F downwards… so each course snakes A1→A6, C6→C1, E1→E6 (seats already allocated are kept; a seat no candidate may take is left empty). **Clear all halls** empties every hall of the session after you type a code shown as an image. Subjects can be imported from another date, typed / pasted in, or brought over from a postponed session (custom dates allowed). Exports at the bottom, in order: **1. Hall Chart** PDF (one page per hall), **2. Entrance Sheet** PDF (all register numbers per course and hall, one page) and **3. Hall Allocation** Excel (per-hall counts with paper-collection order; course codes merged in QP Statistics share one row) and **4. Attendance** — one PDF per course + subject code (old-scheme equivalents merged onto their current subject's sheet; only the current code is shown) in the DOTE attendance-sheet layout (10 candidates a page in register-number order, serial numbers running across pages, spaces for answer book serial number, photo and signature, present / absent counts, Hall Supdt / ACS / CS signatures); download each sheet or all of them as one ZIP. **5. Packing Slips** PDF — one slip per course + subject (courses never merged), six to an A4 sheet with cut lines: QP code box, course / subject code and name, staff name line, and the halls in collecting order (lowest register numbers first), each with a blank line for the count, and a blank total line. **Hall marking guide for DOTE attendance:** upload DOTE's own attendance-sheet PDFs (they only allow printing, so they are not changed); the app reads each row's S.No and register number, takes the hall from this app's seating for the date and session printed on the sheet, and gives a guide PDF listing, page by page, the S.No ranges to bracket for each hall on the printed copies (candidates without a seat show as NOT SEATED). **QR sticker hall separation guide:** upload DOTE's answer-book QR sticker PDF (24 stickers an A4 page; date and session from the file name such as `23102026_FN.pdf`); the guide PDF has one page for each sticker page, with every sticker tinted and labelled with its hall and red cut lines between halls.
8. **Settings** – light / dark / system theme, storage used by each kind of data, **Export / Import** of all data as one JSON file, and **Reset all data** (confirmed by typing a code shown as an image; offers a backup first). All app data is stored locally in this browser.

Every page also reminds you to verify equivalent subjects.

## Data & storage
Everything stays in the browser on this device; nothing is uploaded. Parsed PDFs and all app data (halls, seat allocations, set dates, mappings, candidate edits, a revised time table) are kept in **IndexedDB**, which has room for thousands of students without the 5 MB localStorage limit. Only small display preferences (last tab, theme) use localStorage.

**Upgrading from the old version:** on first start the app moves the old version's halls, seating, added subjects, custom dates and set exam dates from localStorage into IndexedDB, converts set dates to the sittings format and removes the old copies. Backups exported from the old version can be imported in Settings; they are converted the same way.

## View counter
The top bar shows **Today** and **Total Views**. Every page load counts; local copies on `localhost` show the numbers but don't count. Counts are kept by [Abacus](https://abacus.jasoncameron.dev/), a free counting API that needs no account or key: `js/views.js` hits two counters in the `iammannan-ptc-exams-app` namespace, `total` and `day-<YYYY-MM-DD>` (India time, so Today resets at midnight IST).

Notes: Abacus allows 30 requests per 10 seconds per visitor IP, and a counter not used for 6 months expires (old day counters drop off; `total` stays while the site is visited).

## Built-in time table
`js/data/timetable.js` (Board Examinations time table, Version 2 revised 15.10.2026) is generated — refresh it with:

```
npm i --no-save pdfjs-dist@4.10.38
node tools/build-data.mjs --timetable "TT/<time table>.pdf"
```

A revised time table can also be loaded in the app (QP Statistics → *Load revised time table*); it is kept in that browser only.

## Built-in equivalent subjects
`js/data/equivalents.js` is generated from DOTE's equivalent-subject table (tab-separated: course, subject code, name, sem, …, scheme, equivalent code). Refresh it with:

```
node tools/build-equiv.mjs "path/to/equivalents.csv"
```

Only old-scheme rows (K, L, M, N) with a different equivalent code are kept; R2023 rows and subjects mapped to themselves are skipped.

## Run locally
Any static server works, e.g. `npx http-server .` then open http://localhost:8080.

No build step. Libraries (pdf.js, jsPDF, ExcelJS, JSZip) load from jsDelivr on demand.

**Before each release** run `node tools/stamp.mjs`. It tags `styles.css` and every JS module in `index.html` with a version (a hash of their contents, via an import map), so browsers load the new files right after an update instead of cached old ones.
